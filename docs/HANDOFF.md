## 4. 交互契约

### 划词翻译

选中文本 → 按快捷键 → 读取选区 → 在选区附近显示浮层 → 流式展示译文 → 关闭后继续工作。

- 初次显示不激活应用，不抢原应用键盘焦点，不改变原选区或剪贴板。
- 优先使用辅助功能接口读取文本及选区位置；取不到位置时，可在鼠标附近显示并限制在屏幕可见区域。
- 读取失败给出明确提示，允许转入输入窗口，由用户主动复制、粘贴。
- 首版不默认模拟 Cmd+C；避免污染剪贴板及误触发原应用操作。
- 支持再次按触发快捷键收起、点击外部关闭。
- Esc 必须验证不会同时触发原应用的取消动作；在机制确认前不能承诺无副作用的全局 Esc。
- 主动点击浮层时再进入需要的交互。

### 输入翻译

按快捷键 → 小窗口获得输入焦点 → 输入文字 → 提交 → 显示译文 → 关闭。

- 采用用户选定的左右对照结构：左侧原文、右侧共用译文区，引擎切换位于译文上方。
- Return 提交、Shift+Return 或 Cmd+Return 换行（按用户后续确认的 Bob 式交互）；中文输入法确认候选词不能误提交。
- 关闭后恢复原应用；如果用户已主动切换应用，不强制跳回。
- 支持复制译文，不自动粘贴到原应用。

### 请求与错误

- 新请求取消旧请求，并使用请求标识阻止迟到结果覆盖新内容。
- 关闭翻译窗口取消请求；已关闭窗口不能被响应重新打开。
- 空输入不发送；超长输入应有明确限制和提示，不能静默截断。
- 明确区分取词失败、权限缺失、连接失败、模型不存在、超时和中途断流；允许重试。
- 输入文本只作为待译内容，提示词要求仅输出译文、保留段落与代码格式。

## 5. 技术方案

保持一个原生应用工程，不预建插件架构或通用服务框架。

| 职责 | 方向 |
| --- | --- |
| 界面 | SwiftUI：划词浮层、输入窗口、设置 |
| 系统集成 | AppKit：菜单栏、窗口位置、焦点、多屏、全屏场景 |
| 取词 | Accessibility：按需读取前台应用选区，处理授权与不支持场景 |
| 快捷键 | 系统全局快捷键机制，支持重新绑定和注册冲突反馈 |
| 网络 | URLSession：异步请求、流式解析、取消、超时 |
| 配置 | 普通配置本地保存；可选凭据用 Keychain |

### 本地模型

- 设置包含服务类型、地址、模型及连接检查；凭据只在服务需要时填写。
- 优先共用 OpenAI 兼容协议；验证 Ollama 的实际行为后再决定是否单独适配。
- 明确地址字段是 base URL 还是完整 endpoint，避免重复或遗漏 `/v1/chat/completions`。
- 默认使用本机回环地址，无静默云端回退。若以后允许远程地址，应明确显示数据将发送到该地址。
- 对响应状态、流结束、断流、取消和非预期数据做处理。
- 优先非思考模型或服务明确支持的关闭思考参数；不能对任意模型统一追加 `/no_think` 并宣称有效。
- 冷加载时间、首字延迟、完整翻译时间分开记录。先使用现有服务，不擅自下载大模型或重配用户网关。

### 视觉参考的使用边界

效果图是生成式概念稿，不是应用截图或运行证据。保留半透明浅色材质、少量按钮、译文突出、紧凑窗口的方向；实际尺寸与定位以可用性为准。

图中个别文字存在生成误差，例如左侧底部状态文字，实施时统一使用准确的“本地模型”。用户后续已明确要求右上角图钉：钉住后点击外部不关闭，取消钉住后恢复，显式关闭始终有效。

## 6. 开发顺序

| 阶段 | 工作 | 完成门槛 |
| --- | --- | --- |
| P0 环境与验收设计 | 确认工具链、系统、实际模型服务、快捷键、首批应用；在编码前制定检查项 | 知道怎样编译、调用哪个服务、验证哪些场景 |
| P1 交互原型 | 菜单栏、快捷键、取词、简单浮层、输入焦点与恢复 | 核心交互可行；运行验证未经授权则明确标待验证 |
| P2 翻译闭环 | 本地服务连接、划词/输入翻译、流式输出、取消、错误恢复 | 两条路径接入真实模型；标清实际执行的证据 |
| P3 体验打磨 | 参考图样式、深浅色、长文本、中文输入法、多屏定位 | 内容清晰、窗口不越界、操作可预测 |
| P4 打包交付 | 可安装应用、安装授权说明、重启和配置保留检查 | 提供源码、应用及已知限制，未验证项不宣称通过 |

先解决 P1 的取词和焦点风险，再投入视觉细节。最低系统版本、Xcode 工程或 Swift Package 的选择在 P0 根据本机环境确定。
